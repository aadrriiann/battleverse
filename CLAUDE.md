# Battleverse

## 1. Product
- 2D platform fighting game (desktop), one human player vs one AI enemy in an arena.
- Four playable characters: REX, VOLT, NYX, BRUTUS. Each has normal, heavy and special attacks, energy and knockback.
- Flow: `MainMenuScreen` -> `CharacterSelectScreen` -> `GameScreen`. Only ARCADE works; MODO CARRERA, VERSUS and OPCIONES show a "próximamente" toast.
- Users: TODO (student project; audience not stated in the repo).

## 2. Data and backend
- No backend, no database, no network, no save files. All game data is hard-coded in Java.
- Character stats and attacks: factory methods in `core/.../player/CharacterData.java` (`rex()`, etc.).
- Sprites: `assets/sprites/<CHARACTER>/<animation>/<animation>_NN.png`, animations `idle, walk, jump, fall, normal, heavy, special`.
  Frames are loaded by folder listing and sorted by file name, so keep the `_01`, `_02` zero-padded naming.
- Do not touch: `assets/sprites/**` names and folder layout (loader depends on them), `gradle/wrapper/**`,
  `gradle/gradle-daemon-jvm.properties` (generated), `assets/assets.txt` (generated by `generateAssetList`, git-ignored).

## 3. Stack (versions from `gradle.properties` and build files; there is no lock file)
- Java 21 (source/target 21; daemon toolchain 21). Local JDK seen: 21.0.7.
- Gradle wrapper 9.7.1, plugin `org.gradle.toolchains.foojay-resolver-convention` 1.0.0.
- libGDX 1.14.2 (`gdx`, `gdx-box2d`, `gdx-freetype`, `gdx-backend-lwjgl3`). Box2D and FreeType are declared but not used in code yet.
- LWJGL 3.4.3 (forced via constraints). `aiVersion=1.8.2` declared but gdx-ai is not a dependency.
- Packaging: Construo 2.1.0 (native bundles, Temurin 21.0.10). Optional Graal native image (`enableGraalNative=false`).
- Generated with gdx-liftoff.

## 4. Folder map
- `core/` - all game logic, shared by platforms (package `com.battleverse.game`).
- `core/.../screens/` - menu, character select and match screens (`ScreenAdapter` / `Screen`).
- `core/.../player/` - `Player` physics/state, `PlayerController` keyboard input, `CharacterData`, `CharacterAnimation`.
- `core/.../enemies/` - `Enemy` (subclass of `Player`) and `EnemyAI`.
- `core/.../combat/` - `Attack` data, `Hitbox`, `DamageSystem`, `SpecialVfx`.
- `core/.../world/` - `Arena` (bounds, platforms, collision; world 1280x720).
- `lwjgl3/` - desktop launcher (`Lwjgl3Launcher`, `StartupHelper`) and window icons.
- `assets/` - runtime assets; working directory for `lwjgl3:run`.

## 5. Commands (run from `battleverse/`; on Windows use `gradlew.bat`)
- Install: none; the wrapper downloads Gradle and dependencies on first build.
- Dev (run game): `./gradlew lwjgl3:run`
- Lint: TODO (no linter configured; `.editorconfig` only).
- Typecheck / compile: `./gradlew compileJava`
- Test: `./gradlew test` (no tests exist yet; no test dependency configured).
- Build: `./gradlew build`; runnable jar: `./gradlew lwjgl3:jar` -> `lwjgl3/build/libs/Battleverse-1.0.0.jar`
  (`jarWin`, `jarMac`, `jarLinux` for single-OS jars; Construo tasks for native bundles).

## 6. Code conventions
- Reference file: `core/src/main/java/com/battleverse/game/combat/Attack.java` (immutable data class, `private final` fields, getters).
- 4-space indent for Java, 2 for Gradle, LF, UTF-8, final newline (`.editorconfig`).
- Long parameter lists one per line; blank line after a method signature that wraps.
- Sections inside long classes are marked with `// -----` banner comments.
- Static factories for game content (`CharacterData.rex()`), no config files.
- Screens own their `SpriteBatch`, `ShapeRenderer`, `BitmapFont` and free them in `dispose()`.
- Existing comments and in-game strings are in Spanish; global rule says new code and comments go in English. UI text stays Spanish.

## 7. Design system
- No token file or shared UI components. Colours are inline `Color` literals:
  character colours in `CharacterData`, special VFX colours in `SpecialVfx`, HUD bars in `GameScreen`, arena in `Arena`.
- Menu background `0.03, 0.03, 0.06`. Font: default libGDX `BitmapFont` scaled (FreeType not used).
- Virtual resolution 1280x720 with `FitViewport` in `CharacterSelectScreen` and `GameScreen`.
- Sprites use `Nearest` filtering (pixel art); keep it for new textures.

## 8. Environment variables
- `__GL_THREADED_OPTIMIZATIONS` (set by Gradle `JavaExec` tasks; Linux + Nvidia debugging).
- No `.env` and no secrets.

## 10. Known problems
- `Gdx.files.internal(dir).list()` (used in `CharacterAnimation`) does not list directories inside a jar on desktop,
  so sprites may fail to load from `lwjgl3:jar`. Use `lwjgl3:run`, or switch to `assets.txt` / a `TextureAtlas` before shipping.
- `Game.setScreen()` only calls `hide()`; no screen is ever disposed, so textures and batches leak on each screen change.
  Dispose the old screen when switching.
- `MainMenuScreen` draws in raw window pixels (`Gdx.graphics.getWidth()`), unlike the other screens that use a `FitViewport`.
- `CharacterAnimation` hard-codes per-character tweaks (e.g. BRUTUS scale) and special-attack frame timings for 10 frames.
- `GameScreen` (~880 lines) and `Player` (~620 lines) are large; split by responsibility when changing them.
- Unused declared dependencies: Box2D, FreeType, `aiVersion`. Remove or start using them.
- `assets/libgdx.png` and `lwjgl3/src/main/resources/libgdx*.png` are template leftovers (still loaded in `GameScreen`).
- `assets/README.txt` is an instructions note from the sprite ZIP, not game data.
